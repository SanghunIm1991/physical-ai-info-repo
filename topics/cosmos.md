# NVIDIA Cosmos を使ったフィジカルAIの開発

Cosmos は、NVIDIA が開発する、フィジカルAIのための基盤モデルの集まりです。最新の Cosmos 3 は、1つのモデルで、映像の理解と推論（VLM）、先の状態の映像の予測（世界モデル）、ロボットの動作の出力（方策）をこなします。このファイルは、Cosmos を実際に使うエンジニア向けに、ほかのファイルより一歩踏み込んで、モデルの構成・動かし方・追加学習・ロボットでの使い方の要点と、周辺の道具を整理します。Cosmos 3 の短い紹介は [`vlm.md`](vlm.md#cosmos-3) を、NVIDIA の技術全体の中での位置づけは [`nvidia.md`](nvidia.md) を先に読んでください。

- **前提の知識**: 深層学習の基本（Transformer・拡散モデル・追加学習）と、Python・PyTorch を使えることを前提にします。モデルやコマンドの名前は、公式の英語の表記をそのまま併記します。
- **版の扱い**: 確認日の時点の最新は Cosmos 3（2026-05 に公開）です。以前の Cosmos Predict・Transfer・Reason の各リポジトリは、限られた保守だけの段階に入り、Cosmos 3 への移行を勧めています（[版と系譜](#版と系譜)）。数字（パラメータ数・評価の順位など）は、特に断らない限り開発元が示す値です。
- **選び方**: 開発の流れ（データを整える → 追加学習する → 評価する）の各段階から、Cosmos の公式リポジトリ（[NVIDIA/cosmos](https://github.com/NVIDIA/cosmos)）の README が「Platform」の表で案内している3つの道具と、開発元の手引き2つを項目にしました。
- **今回は載せていないもの**: Cosmos 3 の評価の数字の詳細（技術報告の PDF を参照）、自動運転の用途の詳細（Alpamayo は [`nvidia.md`](nvidia.md#alpamayo)）、クラウドのサービスとしての使い方の詳細。

## Cosmos での開発の要点

### 版と系譜

Cosmos 3 は、以前は別々のモデルだった3つの役割を、1つのモデルにまとめました（[公式リポジトリ](https://github.com/NVIDIA/cosmos)・[論文 arXiv:2606.02800](https://arxiv.org/abs/2606.02800)）。以前の各リポジトリは、README の冒頭で「活発な開発は終わり、限られた保守だけを行う」とし、Cosmos 3 への移行を案内しています。

| 以前のモデル | 役割 | 大きさ | Cosmos 3 での扱い |
|---|---|---|---|
| [Cosmos-Predict2.5](https://github.com/nvidia-cosmos/cosmos-predict2.5) | 世界モデル（文章・画像・動画から、先の映像を予測する） | 2B・14B | 生成の部分（generator）が引き継ぐ |
| [Cosmos-Transfer2.5](https://github.com/nvidia-cosmos/cosmos-transfer2.5) | 深さ・輪郭・領域の分割などの映像を条件に、見た目を変えた映像を作る | 2B | 同じく生成の部分。開発元は「変換の能力が大きく上がった」としている |
| [Cosmos-Reason2](https://github.com/nvidia-cosmos/cosmos-reason2) | 映像について推論する VLM（Qwen3-VL の構成） | 2B・8B・32B | 推論の部分（reasoner）が引き継ぐ。[`archive/vlm.md`](archive/vlm.md) も参照 |

Cosmos 3 の大きさは3つです（公式リポジトリの README の表）。

| モデル | パラメータ数 | 動かす先（README の表記） | 開発元が示す用途 | 公開 |
|---|---|---|---|---|
| Cosmos3-Super | 64B | H200・B200・GB200 | 最高の品質、学習用データの生成、蒸留の教師 | 2026-05 |
| Cosmos3-Nano | 16B | RTX PRO 6000・H100・B200 | 速さと品質の釣り合い。追加学習の土台 | 2026-05 |
| Cosmos3-Edge | 4B | Jetson AGX Orin・Thor、RTX PRO 6000 | 機器の上での実時間の方策と映像の推論 | 2026-07 |

- Super と Nano には、重みを FP8 にした版もある。
- 用途ごとに追加学習した例のモデルも公開されている。例えば、ロボットの方策の Cosmos3-Nano-Policy-DROID・Cosmos3-Edge-Policy-DROID、双腕のロボットの映像を作るシミュレーション用の Cosmos3-Nano-Sim-Bimanual、自動運転向けの Cosmos3-Nano-Sim-Auto など。
- Cosmos 3 は Super・Nano が先に出て、Edge が後から出た。開発元の技術解説（2026-05-31）は2つのモデルだけを挙げているので、今の顔ぶれは README で確かめる。

### 2つの塔の構成

Cosmos 3 は、Mixture-of-Transformers（MoT）という構成で、役割の違う2つの「塔」を1つのモデルの中に持ちます（[開発元の技術解説](#cosmos-3-の開発元の技術解説)）。

- **推論の塔（reasoner）**: 画像・動画・文章を読み、文章を出す VLM。自己回帰（1語ずつ順に出す）の作り。単独で呼び出せる。
- **生成の塔（generator）**: 先の映像・音声・動作の系列を、拡散モデルの手順で作る。生成するときは、推論の塔の理解を条件にするので、必ず2つの塔が両方とも動く。情報は推論の塔から生成の塔へ一方向に流れる。
- 開発元は、これで複数のモデルをつなぐ処理の流れを組まずに済むとしている。
- 追加学習の文書（[Cosmos Framework](#cosmos-framework) の training.md）によれば、Super は Qwen3-VL-32B を、Edge は Nemotron-2B-Dense-VL を土台にしている。

入力と出力の組み合わせによって、1つのモデルを次のように使い分けます（開発元の技術解説の表を、このリポジトリが整理したもの）。

| 入力 | 出力 | 使い方 |
|---|---|---|
| 文章 | 画像 | 物理的にありそうな画像の生成 |
| 文章・画像・動画 | 文章 | VLM としての推論（場面の理解・作業の計画など） |
| 文章・画像 | 動画 | 世界モデルとしての予測 |
| 文章・動画 | 動画 | めったに起きない場面（エッジケース）の動画の生成 |
| 動作・動画・文章 | 動画 | 動作を条件にした世界モデル（ロボットをこう動かしたら、どう見えるか） |
| 動画・文章 | 動画・動作 | ロボットの方策（VLA や、映像と動作をあわせて予測するモデル） |

Nano のモデルの公開ページによれば、動作として扱える形は、カメラの動き（9 次元）、自動運転の車（9 次元）、人の視点の動き（57 次元）、Franka の腕とグリッパー（10 次元）、2本の Franka（20 次元）、AgiBot（29 次元）、UR（10 次元）、WidowX 250（10 次元）などです。生成する動画は 5〜400 コマ、推論の塔の入力の長さは最大 256K トークンです（[Nano のモデルの公開ページ](https://huggingface.co/nvidia/Cosmos3-Nano)）。

### 動かす

- **手軽に試す**: README の手始めの例は、Hugging Face の Diffusers から `Cosmos3OmniPipeline` で `nvidia/Cosmos3-Nano` を読み込み、bfloat16 で GPU の上で動かす。生成には安全のための検査の仕組み（guardrail）が既定で入っていて、その部品（`nvidia/Cosmos-1.0-Guardrail`）は利用の申し込みが要るモデルなので、事前に Hugging Face で申し込み、読み取りのトークンで認証する。初回は 16B の重みを取得する（[公式リポジトリ](https://github.com/NVIDIA/cosmos)）。
- **推論の仕組み**: Diffusers・Transformers・vLLM・vLLM-Omni・SGLang・TensorRT-LLM・NIM（NVIDIA のコンテナで包んだ推論のサービス）で動く。開発元の技術解説では、推論には NIM を、追加学習にはリポジトリを勧めている。技術解説の時点（2026-05-31）では、推論の塔の NIM は公開済み、生成の塔の NIM は準備中だった。NIM では、重みを BF16・FP8・NVFP4 から選べ、開発元によれば NVFP4 で推論が最大 2 倍速くなる。
- **動く環境**: Nano のモデルの公開ページによれば、OS は Linux、GPU は Ampere・Hopper・Blackwell の世代で、確かめた精度は BF16 だけ。必要な GPU のメモリの最小値は、読んだ公式の文書には書かれていなかった。

### 追加学習

追加学習は、[Cosmos Framework](#cosmos-framework) で行います（[追加学習の文書](https://github.com/NVIDIA/cosmos-framework/blob/main/docs/training.md)）。

- **手法**: 教師ありの追加学習（SFT）、LoRA、好みのデータでの最適化（DPO）、強化学習（GRPO・PPO・拡散モデル向けの DiffusionNFT）、教師のモデルからの蒸留（OPD）。生成を数段で済ませる「4 段の生徒」のモデルを作る蒸留の手順もある。
- **計算機の目安**: 用意された手順の多くは、H100（80 GB）を 8 枚使う構成で確かめられている。Super の映像の追加学習は LoRA で、8 枚の構成。Edge の映像の追加学習は、GB200 の 4 枚で確かめられている。用途ごとの必要な GPU の数は、作例集（[Cosmos 3 の作例集](#cosmos-3-の作例集)）に S（1 枚・96 GB まで）〜 XL（64 枚を超える）の記号で示されている。
- **ロボットの方策**: 動作の付いたデータで、(1)動作を条件に先の映像を予測するモデル（順方向の動力学）、(2)映像から動作を推定するモデル（逆方向の動力学）、(3)映像と指示から動作の系列を出す方策、を作れる。手順は、DROID（関節の位置の 8 次元の動作）と LIBERO（10 次元の動作）を、Nano から追加学習する例がある。データは、JSONL・WebDataset のほか、LeRobot の形式も読み込める。
- **注意**: 自動運転向けの Sim-Auto のように、すでに蒸留したモデルに、ふつうの SFT をそのままかけない（先に適応させてから蒸留し直す）と、Cosmos Framework の README が注意している。

### ロボットでの使い方

一次情報に示された使い方を、このリポジトリが4つに整理すると、次のとおりです。

1. **学習用データの見た目を増やす**: シミュレーションの映像を、深さや領域の分割を手がかりに、照明・背景・質感の違う写実的な映像に変える（以前の Transfer の役割）。Isaac Lab の模倣学習で、Cosmos で見た目を変えたデータで学習させる例は [`isaac-lab.md`](isaac-lab.md#模倣学習) に、人型ロボットのデータを増やす GR00T-Mimic・GR00T-Dreams は [`nvidia.md`](nvidia.md#isaac-gr00t-のデータ生成の設計図) にある。
2. **ニューラルなシミュレータとして使う**: 動作を条件に先の映像を作り、方策を動かした結果を映像の上で試す。作例集には、双腕のロボットの方策のための対話的なシミュレータを作る例がある。2026-10 には、対話的な世界のシミュレーションの例のモデル・学習の手順・技術報告も公開された（README の更新情報）。
3. **方策そのものとして使う**: 映像と指示から動作を出す。開発元は、Cosmos3-Nano-Policy-DROID を、オープンなものの中で最高水準の DROID の方策としている。
4. **計画と理解に使う**: 推論の塔で、場面の理解・物体の位置の特定（grounding）・作業の計画を行う（README の表の用途）。人型ロボットの VLA の Isaac GR00T N1.7 は、以前の版の推論のモデル（Cosmos-Reason2-2B）を内部の土台に使っている（[`gr00t.md`](gr00t.md#構成)）。

### 注意点

- **品質の限界**: README は、長い・解像度の高い・物理的に複雑な出力では不自然な部分が出ることがあり、安全に関わる用途では追加の確かめが要るとしている。
- **評価の主張**: 開発元は、論文の時点で、外部の順位表（Artificial Analysis の画像・動画の生成、ロボットの方策の RoboArena など）で、オープンなモデルの中で最高だったとしている。いずれも開発元の主張で、このリポジトリは順位表を確かめていない。
- **ライセンス**: Cosmos 3 のコードとモデルは OpenMDW-1.1（Linux Foundation のライセンス）。以前の Predict・Transfer・Reason は、コードが Apache-2.0、モデルが NVIDIA Open Model License で、条件が違う。手順で使う外部のデータセットには、利用の申し込みが要るものがある。

## OSS

### Cosmos Framework

- **概要**: Cosmos 3 などの世界モデルを、学習させ、動かすための枠組み。分散学習（FSDP・テンソル並列などの組み合わせ）、Hugging Face の safetensors との変換、Diffusers・Transformers・vLLM での推論、まとめての生成とサービスとしての提供をそろえる。追加学習の手法は SFT・LoRA・DPO・GRPO・PPO・蒸留などで、手順の多くは H100 の 8 枚で確かめられている。ロボットの方策を、サーバーとクライアントの形で動かす仕組みもある。Cosmos 3 のほか、Isaac GR00T N1.7・π0.5 なども扱えるとしている。
- **一次情報**: [公式リポジトリ](https://github.com/NVIDIA/cosmos-framework)・[追加学習の文書](https://github.com/NVIDIA/cosmos-framework/blob/main/docs/training.md)

### Cosmos Curator

- **概要**: フィジカルAIの学習用のデータ（主に動画）を整えるための道具。動画の分割、説明文の付与、選別、重複の除去、データセットの作成を、部品と参照用の手順を組み合わせて行う。分散処理には Ray Data を使う。Cosmos の学習用のデータの準備を支えるものとして位置づけられている。新しい作業の流れは「Curator Next」から始めることを勧めていて、その API とデータの決まりは育成の段階で変わりうるとしている。
- **一次情報**: [公式リポジトリ](https://github.com/NVIDIA/cosmos-curator)
- **種類**: OSS
- **ライセンス**: コードは Apache-2.0、モデルは NVIDIA Open Model License（README の表記）
- **状態**: 研究段階（README で、Curator Next の API とデータの決まりは育成の段階で変わりうるとしている。正式な版の公開がない）
- **確認日**: 2026-11-13
- **情報源**: 一次

### Cosmos Evaluator

- **概要**: Cosmos のモデルが作った動画の品質を、自動で採点する仕組み。元の動画と変えた後の動画で動きの違いを比べる確認（ないはずの動きが出ていないか）、物体が期待した位置にあるかの確認、言葉で指定した場面の属性を VLM で確かめる確認、動きが物理的にありそうかの確認、の4つを行い、構造化した点数を出す。REST の API の部品と Python の API で使う。学習用のデータを Cosmos で増やしたときに、使えるものを選ぶ用途を想定している（このリポジトリの整理）。
- **一次情報**: [公式リポジトリ](https://github.com/NVIDIA/cosmos-evaluator)
- **種類**: OSS
- **ライセンス**: Apache-2.0
- **状態**: 研究段階（版の番号を示していない。README で、外部からの貢献は受け付けていないとしている）
- **確認日**: 2026-11-13
