# フィジカルAIの最新情報を収集・整理する公開リポジトリ（入門書つき）

## 概要・きっかけ

フィジカルAI（ロボット等、実世界で身体を持って動く AI。Embodied AI とも呼ばれる）の最新情報を収集・整理し、GitHub の**公開リポジトリ**として発信する。情報の一覧だけでなく、初めて触れる人が全体像をつかめる**入門書**を添える。

- **当面のテーマ**:
  1. **RAI**: ROS 2 上でエージェント型の AI 機能を組むためのフレームワーク（RobotecAI が開発。2026-10-17 時点の検索結果による）
  2. **VLM**（Vision-Language Model、画像と言語を扱うモデル）: ロボットの認識・指示理解に使う。VLA（Vision-Language-Action、行動まで出力するモデル）との関係も整理の対象になる
- **成果物**: (1)テーマごとの最新情報の整理（概要・リンク・確認日）。これを主とする、(2)軽く読める日本語の入門書（用語・全体像・各テーマの位置づけ）

**位置づけ**: 「情報を集めて整理し、公開する」企画で、実装の学習は含めない。

## 評価

- **良い点**
  - フィジカルAIは論文・OSS・製品の発表が速く、日本語でまとまった情報は少ないと見込まれる（着手時に確認する）。日本語で全体像を示す入門書には価値がある
  - 公開リポジトリにすると、調べた内容が人の役にも立ち、継続の動機になる
- **懸念点**
  - **鮮度の維持**: 「最新情報」は放っておくとすぐ古くなる。更新の頻度・手順（定期的な見直し、確認日の記載）を決めないと、古い情報を最新として公開し続けることになる
  - **範囲の広がり**: フィジカルAIは範囲が広い（VLA、世界モデル、シミュレータ、ヒューマノイド等）。テーマを絞らないと手が回らなくなる
  - **著作権**: 論文の図・ブログの文章・製品画像を転載できない。リンクと自分の言葉での要約に留める。各 OSS のライセンスも、紹介するだけなら問題になりにくいが、コード片を載せる場合は確認が要る
  - **公開に伴う責任**: 誤った情報や、開発元が「研究開発用」と断っている OSS（RAI の README にはそうした注意書きがあるとされる〈要確認。着手時に README を直接読んで確かめる〉）を実用できるかのように紹介すると、読者を誤らせる。情報の出所（一次情報か二次情報か）と確認日を明記する
  - **個人情報・機微情報**: 公開リポジトリなので、コミットのメタデータ・作業環境のパス・業務に関わる情報が混入しないよう、公開前と push 前の点検が要る
  - **コンテンツのライセンス**: 第三者の著作物を転載しないこととは別に、自分たちが書いた文章（入門書・要約）をどの条件で再利用してよいか（例: CC BY 4.0）を決めて明示する必要がある。リンク集・要約の部分の扱いも含め、着手時に決める
  - **AI が書いた内容であることの明示**: 入門書も情報整理も Claude Code が下書きするため、もっともらしい誤りが混ざりうる。ユーザーが最終確認をしたうえで、Claude Code が下書きした内容である旨を README に明記するかを着手時に決める
  - **情報が増えたときの扱い**: 最新情報を主にするため、項目が増えるほどリンク切れが起きやすく、探しにくくなる。リンク切れの点検の方法と、探しやすくする仕組み（一覧・目次・タグ等）を着手時に決める

## 肉付け（想定する構成）

- **入門書**: フィジカルAIとは何か → 構成要素（認識・計画・制御、シミュレーション、学習）→ 主な技術の地図（LLM／VLM／VLA、強化学習、模倣学習、ROS 2 との関係）→ 各テーマ（RAI・VLM）がその地図のどこに当たるか
- **テーマ別の情報整理**: テーマごとに1ファイル（または1フォルダ）。各項目に「概要・一次情報のリンク・ライセンス・確認日・状態（研究段階／実用）」をそろえる
- **更新履歴**: いつ何を追加・見直したかを残し、情報の鮮度を読者が判断できるようにする
- テーマの追加（VLA、世界モデル、シミュレータ等）は、RAI と VLM が一通りそろってから検討する

## 実現性

技術的な難易度は低い。Markdown と GitHub だけで作れる。難しいのは、(1)最新情報を追い続ける手間、(2)入門書の構成と、正確さの裏取り、(3)公開に伴う点検の手間。情報収集に Claude Code の Web 検索を使えば (1) の負担は減らせるが、内容の正しさの最終確認は人が行う。

## 実現方針（案）

分岐点1〜3は決定、分岐点4は保留（2026-10-17）。残っている未決の点（「着手時に決める」と書いた項目）は着手時に決め、`docs/qa_log.md` に記録する。

- **分岐点1: 「RAI」の指すもの**
  - **決定: RobotecAI の RAI（ROS 2 向けのエージェントフレームワーク）**
- **分岐点2: 入門書と情報整理の比重**
  - 選択肢A: 入門書を主にし、最新情報はその補足とする（内容が古くなりにくい）
  - 選択肢B: 最新情報の整理を主にし、入門書は読み方の案内に留める（鮮度で勝負する）
  - **決定: 選択肢B（最新情報の整理が主、入門書は軽く読める補助）**
  - 最新情報が主なので、各項目の確認日・状態（研究段階／実用）の記載と、古くなった項目の扱い（削除するか「古い」と明記して残すか）が重要になる。古い項目の扱いは着手時に決める（Claude の補足）
- **分岐点3: 入門書の言語と分量**
  - 選択肢A: 日本語のみ（日本語の情報が少ないと見込まれる点に合う）
  - 選択肢B: 日本語と英語の両方（読者は増えるが、手間が倍になる）
  - **決定: 選択肢A（日本語のみ）。分量は軽く読める程度に留める**。入門書は Claude Code に書かせ、ユーザーが内容を確認する
  - 軽く読める程度に留めるため、入門書は全体像と用語の説明に絞り、各技術の詳細はテーマ別の情報整理のリンク先に任せる（Claude の案）
- **分岐点4: 更新の頻度と手順**
  - 選択肢A: 決まった周期（月1回など）で見直す
  - 選択肢B: 大きな発表があったときだけ更新する
  - **保留**: 当面は、ユーザーが更新を依頼したときに Claude Code が調べて更新する。定期的な更新の仕組みは、運用してから必要に応じて決める
  - 依頼のたびに調べ方がぶれないよう、Claude Code に調べさせる手順（検索の範囲・情報源の信頼の基準・確認日の書き方）を手順書かプロンプトとして固めるかは、着手時に決める
- **情報源の扱い（Claude の案）**: 一次情報（論文〈arXiv 等〉、公式リポジトリ、公式ドキュメント、開発元の発表）を優先し、二次情報（解説記事等）はその旨を書き添える。URL は推測せず、実在を確かめたものだけを載せる
- **公開について**: このリポジトリは公開（Public）を前提とする。公開前の点検（内容・コミットのメタデータ・第三者の著作物）を行う
