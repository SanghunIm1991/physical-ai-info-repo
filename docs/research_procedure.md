# 情報の集め方・確かめ方の手順

このリポジトリの項目を追加・更新するときの手順。更新を依頼されたときに、調べ方がぶれないようにするために置く。Claude Code が調べて下書きし、管理者が内容を確認してから公開する。

## 1. 調べる範囲

- 対象は、各テーマのファイルの説明に書いた範囲に限る。範囲の外で見つけたもの（別のテーマに当たるもの）は、項目にせず、テーマの追加の候補として管理者に伝える。
- 新しいテーマの追加は、管理者が判断する。

## 2. 情報源の信頼の基準

| 区分 | 例 | 扱い |
|---|---|---|
| 一次情報 | 論文（arXiv・学会の論文集等）、公式リポジトリ、公式ドキュメント、開発元の発表 | 項目の根拠にする。優先して使う |
| 二次情報 | 解説記事、ブログ、ニュース、動画 | 一次情報が見つからない場合だけ使い、「情報源: 二次」と概要の注記で明示する。一次情報が見つかった時点で差し替える |

- 検索結果の要約や、AI が生成した説明だけを根拠にしない。必ずリンク先の本体を読む。
- 開発元の主張（性能・対応範囲等）は、「開発元によれば」のように主張であることが分かる書き方にする。

## 3. URL の扱い

- URL は推測で書かない。実際に開いて中身を確かめたものだけを載せる。
- 公式のものを優先する（例: 論文は arXiv の要旨のページ、OSS は公式リポジトリ）。
- 移転・削除でつながらなくなったものは、公式の案内で新しい URL を確かめて差し替える。見つからなければ、その項目をアーカイブに移すか管理者に相談する。

## 4. 各欄の書き方

- **概要**: 自分の言葉で書く。元の文章を訳しただけの文や、長い引用は使わない。
- **ライセンス**: 開発元の表記（LICENSE ファイル・README 等）のとおりに書く。確かめられなければ「未確認」と書く。
- **状態**:
  - 研究段階: 開発元が研究・試作・実験向けとしている、論文の実装にとどまる、正式な版（1.0 等）が出ていない、のいずれか
  - 実用: 開発元が実運用向けとして提供し、正式な版や製品として出ている
  - 判断に迷う場合は「研究段階」とし、根拠を括弧で書く
- **確認日**: 一次情報を実際に確かめた日を YYYY-MM-DD で書く。内容を変えなくても、確かめ直したら更新する。

## 5. 更新の手順

1. 対象のテーマのファイルの各項目を、一次情報で確かめ直す（変更点・リンク切れ・状態の変化）。
2. 新しい項目を探して追加する（上の基準に合うものだけ）。
3. 古くなった項目（開発の停止、後継の登場、公開の終了など）は、`topics/archive/<テーマ>.md` に移す。移すときは、移した日と理由を項目に書き足し、後継があればリンクする。状態は、移した理由に合わせて「開発終了」「公開終了」のように書き換えてよい。テーマのファイルの一覧表からは外す。
4. `CHANGELOG.md` に、日付と、追加・見直し・移動した項目を書く。
5. リンクを点検する。対象は `topics/` のファイルだけでなく、README・入門書（`primer.md`）など、リポジトリの Markdown のすべてとする。相対パスのリンクの先が実在するか、一覧表から見出しへのリンクが飛べるか、外部リンクがつながるか（外部リンクは、ドメインの一覧を管理者が見てから、HEAD の要求だけで確かめる）。つながらないものは「3. URL の扱い」に従う。
6. 管理者が内容を確認する。

## 6. 書いてはいけないもの

- 第三者の文章・図・画像の転載（リンクと自分の言葉の要約に留める）
- コード片は、ライセンスを確かめてから、必要な最小限だけ載せ、出典とライセンスを書く
- 作業環境や管理者の個人的な事情に関する記述
